# 웹문서 대량제작 상품 — 판매 사이트 기획 (2026-10-29 초안)

> 파워크레인.kr(crain_prj)에 적용한 "키워드 하나 = 페이지 하나" 구조를 다른 사장님들에게 상품으로 판다.
> 키워드 목록: `keywords/웹문서대량제작_키워드.xlsx` (생성기 `gen_webdoc_keywords.py`)

## 1. 상품 한 줄

영업 지역 × 서비스 조합마다 검색 페이지를 하나씩 만들어, 블로그·플레이스로 못 닿는 지역 검색에 사장님 업체가 걸리게 한다.

- 영업 지역 × 서비스로 검색 페이지 수백~수천 개 제작, 단계별 오픈
- 사장님 홈페이지·블로그의 **실제 사진과 시공 사례**로 내용 구성 (지어낸 후기·수치 없음)
- 페이지마다 전용 썸네일(OG), 전화 버튼, 네이버 플레이스 연결, FAQ·구조화 데이터
- 네이버 서치어드바이저·구글 서치콘솔 등록, 사이트맵·RSS 제출, 수집 요청까지

## 2. 어디서 파나

**ad.jd8.co.kr 안에 "웹문서 대량제작" 섹션**으로 붙인다(마케팅 대행 사이트와 고객층이 같고, 지역·서비스 페이지 652개와 블로그 루틴이 이미 돈다).
- 대표 사례: **파워크레인.kr** — 키워드 3,376개 → 페이지, 4단계 오픈, 페이지별 썸네일·캐러셀. 사장님 허락 받고 화면·수치 공개.
- jd8.co.kr 업종 페이지에서 "홈페이지 있는데 검색이 안 되면" 링크로 교차 유입.

## 3. 페이지 구성 (구현됨 2026-10-29 — 키워드 5,370개 → 페이지 176개 + 허브)

| 유형 | URL | 수 | 내용 출처 |
|---|---|---|---|
| 허브 | `/웹문서/` | 1 | 업종군별 목록·계산기·예시 화면 |
| 핵심 | `/웹문서/웹문서-대량제작/` 외 | 8 | `content/webdoc/*.md` (원고) |
| 업종 | `/웹문서/하수구-홍보/` | 168 | `data/webdoc/industries.json` + `lib/webdoc.ts` 조합기 |
| 블로그 | `/blog/…` | 1,684 | 기존 ad.jd8 자동 발행 큐(`data/keyword-queue.json`)에 2:1로 섞음 |

- 지역만 바꾼 "인천 웹문서 제작" 같은 페이지는 내용이 같아져 만들지 않음 → 지역 키워드는 핵심 페이지가 받는다.
- 단계 오픈: `lib/webdoc.ts` LAUNCH=2026-10-29, D0 25%(44) → D2 50% → D4 75% → D6 100%. 서버 하루 2회 빌드로 날짜만 지나면 자동으로 열린다.
- 법률·회생·금융 업종군은 '사무소·상담·고객·대표님' 어휘, 표시 규정 박스 자동 출력.
- 썸네일: `python scripts/webdoc_og.py` → `public/og/webdoc/*.jpg` (업종 추가 시 다시 실행).
- 점검: 본문 평균 1,675자, 같은 문장 평균 11%·최대 17% (dup_measure), static_audit 문제 없음.

## 4. 콘텐츠 메시지 3갈래

**① "이 자리에 사장님 업체가 나옵니다"** — 썸네일·히어로
- 페이지별 OG 썸네일 자동 생성: 네이버 검색 결과 모양 위에 `김포 하수구 → 이 자리에 사장님 업체` (중요 글자는 가운데 630×630 안).
- 히어로에 실제 검색 결과 목업 + "지역 25곳 × 서비스 12종 = 300페이지" 식 계산.

**② 타지역 서비스는 블로그·플레이스로 안 된다** — 공감 섹션
- 플레이스는 사무실 거리순이라 출장 업종은 옆 동네에서 안 보인다.
- 블로그는 저품질·누락에 매번 새 글을 써야 하고, 체험단은 지역마다 못 돌린다.
- 파워링크는 클릭마다 돈이 나간다. 웹문서는 한 번 만들면 남는 자산.

**③ SEO · GEO · AEO** — 차별화 섹션
- 검색엔진(SEO) + AI 답변(GEO·AEO: 챗GPT·네이버 AI 브리핑·구글 AI 개요)이 인용하는 구조: 상단 핵심 요약, 질문형 소제목, FAQ, 구조화 데이터.

## 5. 페이지 템플릿 (업종 페이지 기준)

1. 히어로 — H1 = 대표 키워드, 검색 결과 목업 썸네일, 카톡 상담
2. 문제 공감 — 그 업종의 타지역 수요 특징(출장 범위·성수기·긴급성) — 업종 데이터에서 주입
3. 이렇게 만듭니다 — 예: `{업종}` 영업 지역 × 서비스 조합 예시 표 (실제 생성될 페이지 이름 10개)
4. **페이지 수 계산기** — 지역 수·서비스 수 입력 → 예상 페이지 수 (정적 JS, 전환 도구)
5. 사례 — 파워크레인 (화면, 페이지 수, 단계 오픈 일정)
6. 포함 항목 — 썸네일·전화 버튼·플레이스 연결·사이트맵·등록·수집 요청
7. 진행 단계 — 키워드 설계 → 자료 받기(사진·사례) → 1단계 오픈 → 색인 확인 → 단계 확장
8. FAQ — 노출 보장? (불가 + 이유) / 양산형 아닌가? (실제 사진·유사도 검사) / 기간 / 기존 홈페이지 있으면?
9. 카톡 CTA

데이터 축(`data/webdoc-industries.json` 예정): 업종별 출장 범위, 긴급성(24시간 여부), 성수기, 대표 서비스 종류, 고객이 쓰는 검색 표현.

## 6. 꼭 지킬 원칙

- **소비자 검색어로 우리 판매 페이지를 노출하지 않는다.** "김포 하수구"를 찾는 사람은 하수구 업체를 찾는 것이라, 광고 판매 페이지에 오면 바로 나가고 스팸 신호가 된다. 타깃은 사장님이 쓰는 말(홍보·마케팅·웹문서·타지역)만. "이렇게 만들어집니다" 예시 페이지는 이미지로 보여주거나 noindex.
- **"최저가" 문구는 근거(비교 기준·가격 공개) 없이 쓰지 않는다** — 표시광고법 리스크. 가격표를 공개하고 "합리적" 정도로.
- "상위노출 보장" 금지. 대신 "단계 오픈 → 색인 확인 → 확장" 과정과 월간 리포트를 판다.
- 고객 납품 페이지도 같은 품질 기준(실제 사진, 유사도 검사, 페이지별 OG·캐러셀). 서브도메인 원페이지 팜(qelvuno식)은 만들지 않는다.
